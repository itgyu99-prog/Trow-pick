# TROW PICK · 트로우 픽

React + TypeScript + Vite / Node.js + Express + Socket.IO로 만든 2~15인 카드 파티게임입니다. 서버가 53장 트럼프와 44장 트로우를 관리하며 22종 효과를 입력 대기 상태머신(Generator)으로 실행합니다. 빠른 매칭은 실제 접속자끼리만 연결합니다.

## 혼자 AI와 실험하기

닉네임 입력 → 우리끼리 방 만들기 → **AI 추가** → **게임 시작하기**. 방장은 대기실에서 AI를 최대 14명 추가하거나 제거할 수 있으며, 사람과 AI를 섞어 최대 15명까지 플레이할 수 있습니다. AI는 참가 명단에 명시됩니다. 종료 후 다시 한 판에도 유지되며 대기실로 돌아가 구성 변경이 가능합니다.

AI는 외부 API 없이 서버에서 실행되는 규칙 기반 봇입니다. 약 3초 생각한 뒤 현재 요청의 선택지를 고릅니다. 자기 손패와 해당 효과가 공개한 정보만 사용하고, 숨겨진 상대 카드나 트로우 순서는 보지 않습니다. 공개된 짝 카드를 우선 뽑고, 전달 시 조커를 우선 넘기는 등 간단한 전략을 사용합니다. 줄·예측·상대 지목은 무작위이며, 공개 연출은 사람과 동일하게 2초를 기다립니다. `server/bot.ts`와 `RULES.botThinkMs`에서 전략과 속도를 변경할 수 있습니다. AI가 방장 권한을 받거나 실제 매칭 인원으로 채워지는 일은 없습니다.

## 실행

Node.js 22 이상 권장. 프로젝트 폴더에서:

```sh
npm install
npm run dev
```

브라우저: http://localhost:5173 · 백엔드: http://localhost:3001

```sh
npm test
npm run build
npm start
```

프로덕션에서는 http://localhost:3001 에서 화면과 Socket.IO를 함께 제공합니다. `PORT` 환경변수로 서버 포트를 바꿀 수 있습니다. 개발용 Vite 프록시는 기본 백엔드 포트 3001을 사용합니다. `.env.example`은 참고 파일이며 개발 실행 시 PowerShell에서 `$env:PORT='3001'` 등으로 환경변수를 지정하세요.

## 친구 초대 / 자동 매칭

닉네임 → 방 만들기 → 초대 링크 복사 → 다른 기기나 브라우저가 링크에서 닉네임과 참가 버튼으로 입장 → 방장이 시작합니다. 링크 `/room/ABCDE`는 게임 화면이 아닌 해당 코드의 참가 화면을 엽니다. 새 참가자는 진행 중인 게임에 들어갈 수 없습니다.

빠른 매칭은 같은 서버의 공개 매칭 대기실에 실제 접속자를 모읍니다. 2명 이상이면 8초 뒤 시작하며 그동안 최대 15명까지 들어갑니다. 이용자가 혼자라면 계속 기다립니다. 대기실에서 방장이 조기 시작할 수도 있습니다.

한 PC에서는 별도의 탭 또는 브라우저로 테스트하세요. 재접속 토큰은 각 탭의 sessionStorage, 닉네임과 움직임 설정은 localStorage에 보관합니다. 탭 복제는 같은 토큰을 복제할 수 있으므로 주소를 새 탭에 직접 여세요. 같은 토큰으로 재접속하면 기존 연결이 종료됩니다. 브라우저 새로고침과 일시적 네트워크 단절은 같은 자리로 복귀합니다. 탭을 완전히 닫으면 토큰 복구가 보장되지 않습니다.

같은 Wi-Fi의 다른 기기에서는 개발 서버가 표시하는 Network 주소를 사용하세요. localhost 초대 링크는 다른 기기를 가리키지 않습니다. 방화벽이 허용되어 있어야 합니다. 실제 외부 접속은 아래 서버 배포가 필요합니다.

## 게임 규칙과 임시 설정

- 기본 53장을 고르게 분배하고 숫자가 같은 두 장을 제거합니다. 무늬는 무관합니다.
- 첫 분배 때의 짝은 자동 정리됩니다. 이후 게임 중 생긴 짝은 테두리가 빛나며 손패에 남아 있습니다. 효과 처리가 끝나면 소유자가 확인하고 버립니다. 다른 사람에게 생긴 짝은 그 사람이 먼저 확인하고, 현재 턴 플레이어가 마지막에 **짝 버리고 턴 넘기기**(짝이 없으면 **턴 넘기기**)를 눌러 턴을 마칩니다. 시간 초과·연결 끊김 때는 기존 자동 선택 규칙을 적용합니다.
- 트로우는 턴 시작 후 더미 또는 **트로우 카드 뽑기** 버튼을 눌러야 소모·공개됩니다. 다른 사람은 대신 뽑을 수 없습니다. 트로우가 모두 소진되면 바로 일반 뽑기를 합니다. AI는 이 단계도 3초 후 자동 처리합니다.
- 시작 방향과 시작 플레이어는 무작위, 기본 대상은 진행 방향의 다음 생존자입니다.
- 22종을 각 두 장씩 사용합니다. 사용한 인스턴스는 돌아오지 않으며 44장 소진 후 일반 뽑기를 합니다.
- 효과에 필요한 줄, 카드, 예측, 상대 지목, 전달, 남길 카드 선택을 기다립니다. 몰아주자의 남길 카드는 실제 카드 소유자가 고릅니다.
- 동시에 비운 사람은 같은 순위입니다. 다음 순위는 인원만큼 건너뛰는 경쟁 순위(1, 1, 3)를 사용합니다.
- 조커는 정확히 1장이며 총 53장으로 플레이합니다. 조커는 짝이 되지 않고 마지막 보유자가 최하위가 됩니다.
- 꿈꾸는 어른: 뽑기 후 무작위 순서의 다른 생존자에게 직접 고른 카드를 한 장씩 전달하며, 전달 직전 손패가 한 장이면 중단합니다. 짝 정리로 마지막 패가 없어지는 것은 허용합니다.
- 다시햇!: 현재 생존자의 패만 섞어 재분배하며, 현재 턴의 뽑기 후 전원 짝 정리와 순위를 판정합니다.
- 자동 교환 가능한 후보가 여러 개면 서버가 무작위 선택합니다. 이미 버린 카드와 순위 확정자는 대상에서 제외합니다.
- 석 아웃의 짝 제한은 해당 플레이어의 다음 턴이 시작할 때 해제됩니다. 아앗..의 동일 카드 재선택은 허용합니다.
- 턴 입력은 30초, 공개는 2초입니다. 입력이 없으면 현재 선택지 첫 번째를 서버가 선택합니다. 효과마다 새 제한 시간이 주어집니다.

임시값은 `shared/types.ts`의 `RULES`에 모았습니다. 조커 짝 판정은 `pairable`, 최고 카드 비교는 `comparisonValue`, 게임 종료는 `Game.terminal`로 분리했습니다. 조커 규칙을 바꾸면 관련 종료 테스트도 함께 확인하세요.

## 서버와 개인정보 경계

`server/game.ts`: 카드 이동, 교환, 전체 패 교환, 재분배, 짝 정리, 순위, 22종 효과 레지스트리. 매 입력 후 카드 총수·고유 ID·원본 카드 내용·트로우 인스턴스를 검증합니다.

`server/index.ts`: 방, 매칭, 세션, Socket.IO, 개인별 상태 직렬화. 일반 상대 패는 개수만 보냅니다. 카드 선택 키도 서버의 실제 카드 ID가 아닌 해당 선택의 인덱스입니다. 공개 효과에서만 필요한 앞면을 전달합니다. 현재 actor와 선택 revision을 검증해 재전송·차례 외 입력을 거절합니다. 연결별 요청 횟수와 패킷 크기에 제한을 둡니다.

게임 도중 연결이 끊겨도 패를 보존하며 시간 초과 시 자동 행동합니다. 방장은 온라인 참가자로 이전합니다. 게임 전 나가기는 명단에서 제거하고, 종료 후 대기실 이동은 오프라인 참가자를 제거합니다. 전원 오프라인인 방은 10분 후 정리합니다.

현재 상태는 단일 Node 프로세스 메모리에 있습니다. 서버 재시작·재배포 시 방이 사라집니다. 다중 인스턴스나 영구 복구가 필요하면 외부 저장소 및 Socket.IO 어댑터를 추가해야 합니다. 지금 구성은 단일 서버에서 운영하세요.

## 테스트

`npm test`는 2·4·6·8·15인 각 100판 시뮬레이션, 22종 각각 반복 실행, 모든 단계의 53장/44장 보존, 차례·중복 입력 거부, 조커 보유자 최하위, 트로우 소진을 검사합니다. 실제 소켓 테스트는 임시 서버(3099 포트)를 열어 초대 참가, 방장 권한, 정보 제한, 재접속, 권한 이전, 8초 자동 매칭을 검증합니다. 네트워크 테스트 실행에는 로컬 소켓 권한이 필요합니다.

브라우저에서는 방 생성 → 초대 참가 → 시작 → 직접 카드 선택 → 종료 → 다시 플레이를 확인하세요. 모바일 게임 화면과 대기실은 `100dvh`에 맞춰 페이지 전체가 세로로 길어지지 않도록 구성했습니다. 세로 화면은 참가자 → 트로우 → 행동 → 손패 순서로 배치하고, 가로 화면은 오른쪽에 손패를 둡니다. 참가자·선택 카드·손패가 많으면 해당 영역만 스크롤하며, 짧은 화면은 간격과 장식을 줄입니다. 종료 순위와 긴 안내도 각 패널 안에서 스크롤합니다. 노치와 홈 표시줄은 safe-area 여백으로 처리합니다.

뽑기 연출은 선택한 카드가 받는 사람의 손패 끝자리(다른 사람은 좌석)로 바로 이동하는 650ms 애니메이션입니다. 받은 본인에게만 앞면을 뒤집어 보여주며 다른 사람과 AI의 카드는 뒷면입니다. 연속 뽑기는 서버가 발급한 순번으로 큐에 넣고, 재접속 시 과거 연출은 재생하지 않습니다. 실제 게임 상태를 지연시키지 않고 연출만 재생합니다. 모션 중 다음 선택은 잠깐 비활성화합니다. 설정의 움직임 줄이기 또는 OS의 reduced-motion 설정에서는 모션을 숨깁니다. 교환·전달·전체 재분배의 개별 이동 연출은 추가 개선 대상입니다.

## 배포 준비 (아직 공개 배포하지 않음)

`Dockerfile`, `.dockerignore`, `render.yaml`을 포함했습니다. 화면과 서버를 하나의 서비스에 배포하면 웹소켓 주소, CORS, 초대 링크가 같은 도메인에서 동작합니다. 서버가 `/room/*` 경로도 index.html로 제공하므로 초대 링크 직접 접속을 지원합니다.

Render에 Git 저장소를 연결하고 Blueprint로 `render.yaml`을 선택하거나 Docker Web Service로 생성하세요. 빌드 후 제공된 HTTPS 주소로 접속하면 됩니다. [Render WebSocket 문서](https://render.com/docs/websocket), [무료 서비스 제한](https://render.com/docs/free)을 참고하세요. 무료 서비스는 유휴 시 중지될 수 있어 첫 접속 지연과 메모리 방 소실이 생길 수 있습니다.

다른 서버에서는 `docker build -t trow-pick .` 후 `docker run -p 3001:3001 trow-pick`으로 실행하고 HTTPS 리버스 프록시에서 WebSocket Upgrade를 전달하세요. 프론트엔드만 정적 호스팅에 올려서는 멀티플레이가 작동하지 않습니다. 이 프로젝트는 같은 출처 배포를 기본으로 하며, 프론트·백엔드를 분리하려면 명시적 Socket.IO URL과 서버 CORS 허용 출처를 추가해야 합니다.

현재 외부 서버 계정/배포 URL은 연결되어 있지 않습니다. 로컬 테스트 성공이 공개 배포 성공을 의미하지 않습니다.

## 상대 손패 선택과 효과 안내

뽑기 단계에서는 모든 플레이어에게 대상의 이름·손패 수와 부채꼴로 펼친 선택 카드가 나타납니다. 현재 뽑는 사람만 선택할 수 있으며, 누가 고르는지와 고른 위치가 모두에게 보이고 선택한 카드가 실제 패 위치에서 손패·좌석으로 이동합니다. 반쪽짜리 행운의 앞면과 빛을 보았어의 강조는 뽑는 당사자에게만 전달하며 관전자에게는 키를 숫자로 바꾼 뒷면 선택지만 서버에서 직렬화합니다. 선택 완료 장면은 850ms 유지한 뒤 다음 입력을 보여줍니다. 카드가 많으면 펼친 패 영역을 가로로 넘겨 선택할 수 있습니다. 별도의 트로우 단계 안내 상자는 표시하지 않습니다.

개봉박두는 사용한 플레이어의 손패만 모든 참가자에게 2초간 공개합니다. 다른 사람의 손패는 공개되지 않으며, 2초 후 공개를 끝내고 다음 생존자의 카드를 고릅니다.
